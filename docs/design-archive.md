# Docszine 设计存档

更新时间：2026-09-16

这份文档记录 Docszine 后续开发可复用的视觉来源、设计过程中的约束，以及 Classic Theme 实现时不能悄悄改变的基础假设。它来自 ChatGPT 项目对话“wordprss classic theme - 分支 · 调研文档建站系统”和其中最终确认的静态 HTML。静态文件仍保留原始 `humanities-docs-*` 文件名，作为参考样本，不代表 Docszine 的品牌名称。

## 设计核心

- 信息路径是“首页 → 章节索引 → 内容页”，不是营销首页 → 卡片 → 独立落地页。
- 整体应像安静的文档、研究资料或参考书：白色阅读面、柔和浅灰背景、细分隔线、克制的单一橙色强调色 `#e87917`。
- 避免 dashboard、过度卡片化和宣传页式大面积装饰。层级、留白、阅读节奏比装饰优先。
- 视觉基准使用系统字体栈，桌面端阅读宽度约 620px，正文旁可以有内部注释/图像轨道。

## 响应式和导航规则

- 桌面端：左侧固定 Docs Tree，中间为阅读面，文章页可有右侧“本页目录”。
- 平板端（约 900/768px）：全局侧栏收进抽屉，但文章内部的阅读轨道仍可保留；外侧留白约 28px。
- 手机端（约 390px）：内容变为单列；全局菜单、章节树和本页目录分别通过抽屉进入。不要把桌面几何图形硬缩小，要保留图像和正文的编辑感。
- 抽屉需要处理滚动锁定、键盘焦点、ARIA 状态和必要的 `inert` 行为；遮罩、章节抽屉、本页目录的层级不能互相遮蔽。已知参考实现中遮罩约为 1090、抽屉约为 1110。
- 树形导航中，箭头只负责展开/收起，标题链接负责导航。当前章节和当前页面应有不同的选中状态。首版支持 2–3 层，不能把任意深度层级写死在 CSS 中。

## 内容页面语法

- 保持真实的 H1/H2/H3 语义；H2/H3 生成稳定的本页目录锚点。
- H2 进入文章内部轨道并形成清晰的章节分隔；页面摘要/导语用于建立阅读入口。
- 文章底部提供按文档树深度优先顺序计算的上一页/下一页。
- 图片需要区分标准图、边缘/浮动图、突破阅读宽度图、双图和轮播。移动端必要时取消浮动与文字环绕，但保留双图和轮播的编辑意图。

## WordPress 实现边界

- WordPress 负责内容数据库、编辑、媒体、修订、搜索、权限和页面层级；前端呈现由 Classic Theme 控制。
- 以原生 Pages、父页面、菜单顺序和摘要表达 Docs Tree，不新增 Docs Custom Post Type。这样用户更换主题时，内容仍是普通 WordPress 页面。
- 主题负责模板层级、文档树、阅读布局、响应式导航、站点标识、搜索、归档、404、Feed、评论和小工具等标准入口。
- Docs Root Page 通过 Customizer 设置，不把根页面 ID 写死在模板里。
- 编辑器专属语义（aside、historical、context、definition 等）和轮播短代码可以放入小型 companion plugin；主题核心不能依赖插件才能输出普通 Pages/Posts。
- 编辑内容优先使用可编辑的语义 HTML；保留旧短代码兼容时，应让插件负责解析，主题负责安全显示。

## 安全和质量约束

- 不能把可编辑文案、页面 ID、菜单结构或站点数据硬编码进主题；演示内容放在独立的 content/导入资产中。
- 所有输出按上下文转义；允许的编辑 HTML 使用 `wp_kses_post()` 或更窄的白名单；禁止事件属性、`javascript:` URL 和未过滤的原始 HTML。
- 能力检查应按实际 post type 使用，例如页面编辑使用 `edit_pages`，不要只做宽泛的 `edit_posts || edit_pages` 判断。
- 主题/插件不新增自定义上传、文件写入、删除、直接 SQL、远程运行时请求、动态 include、命令执行或反序列化路径。
- 参考对话中的安全审查针对 Humanities Docs 1.0.0 旧产物；它不能代替 Docszine 当前代码的真实 WordPress、KSES、Theme Check 和 staging 验证。
- 每次重要改动至少检查 1440、1180、1024、900、768、390px；同时检查键盘操作、焦点可见性、200% 缩放、减少动态效果、RTL 和长标题/长 URL。
- 站点部署层另行保持 `DISALLOW_FILE_EDIT`、双因素认证、SFTP/SSH、及时更新、删除不用的插件/主题、异地备份和必要的日志/WAF。

## 版本和使用方式

原始静态样本在对话中最后整理为 Humanities Docs 1.0.0。Docszine 可以复用这条文档型阅读路线，但它自己的品牌、杂志/编辑内容模型和现有主题代码仍以本项目文件为准；下列 HTML 仅用于核对视觉语法，不应直接放入可发布的主题 ZIP，也不应把 `Humanities` 或 `FIELD NOTES` 当作 Docszine 的部署品牌。

如果设计发生变化，先更新本存档，再修改主题和示例内容。开发时优先用静态样本核对布局、导航状态、阅读宽度和响应式行为；WordPress 的 URL、查询和内容来源则以主题的模板层级和现有内容模型为准。
